# IO Guard 中文学术数据评测报告（2026-08-12）

## 结论

本轮使用同行评审论文的官方数据，对 IO Guard 的输入、外部内容和输出三阶段进行中文评测，并补充规则、BGE 相似度算法和微调 Transformer 分类器的专项测试。

发现并修复了以下问题：

1. 输出侧把普通语义中的“内部”“秘密”“机密”等词直接当作数据密级，AlignBench 正常输出的误拦截为 `17/683`。增加密级上下文约束后降为 `1/683`，剩余一条包含真实邮箱，符合既定输出脱敏策略。
2. 中文“不要理会此前要求”“将内容视为系统指令”等同义间接注入缺少规则覆盖，已增加输入规则和外部内容过滤规则。
3. Base64 解码后已经确认命中提示注入，但 `encoding_obfuscation` 未进入阻断风险集合，只返回人工审核；现已按高分证据阻断。
4. 输入和外部内容在检测前被规范化，零宽字符先被删除，导致混淆证据丢失；现改为由注入检测器同时接收原始文本，规范化后的文本仍供其余流水线使用。规则只在零宽字符拆分风险短语或异常重复时升级，保留 emoji 的 ZWJ 和单个排版字符，避免正常格式误报。
5. BGE 风险相似度在 AlignBench 英文输出抽样上出现两条跨语言误报，已补充英文正常输出原型；修复后分层抽样误报为 `0/336`。
6. v2 微调 Transformer 分类器在内部测试集表现正常，但在独立学术数据上存在严重分布外误报。本轮未通过降低阈值掩盖问题；所有 Transformer 策略均标记 `production_ready=false` 并增加显式实验门禁，待重训和独立校准后再上线。

## 数据来源

| 数据集 | 论文/会议 | 用途 |
|---|---|---|
| SafetyBench | ACL 2024 | 11,435 条中文安全分类问题，输入侧正常安全讨论与敏感主题硬负例 |
| Chinese Do-Not-Answer | Findings of ACL 2024 | 2,726 条中文有害、漏判和误判问题，用于模型分布外分析 |
| AlignBench | ACL 2024 | 683 条高质量中文问题和参考回答，输入、输出正常样本误报评测 |
| InjecAgent | Findings of ACL 2024 | 工具智能体间接提示注入结构，转换为中文外部内容测试 |
| BIPIA | KDD 2025 | 间接注入攻击和正常任务结构，转换为中文外部内容测试 |
| JailbreakBench | NeurIPS 2024 Datasets and Benchmarks | 越狱攻击与配对良性请求结构，转换为中文输入测试 |

仓库只提交最小、可追溯的改写/翻译测试夹具，不提交完整第三方数据。每条夹具保存来源数据集、记录编号和派生方式。

## 覆盖范围

### 输入侧

- NFKC 与零宽字符混淆；
- 中英文提示注入与中文同义改写；
- 越狱和策略绕过；
- Base64 编码注入；
- 短回复指令劫持；
- 字符、估算 Token、工具调用和耗时预算；
- 安全讨论、敏感主题和正常业务问题硬负例；
- 可选 BGE 风险相似度和微调 Transformer 分类器。

### 外部内容侧

- InjecAgent 风格工具调用注入；
- 数据外传指令；
- BIPIA 风格任务替换、语言转换等间接指令；
- 危险片段删除、事实保留和长度瓶颈；
- 输入规则、过滤规则与语义模型的阶段边界。

### 输出侧

- 手机、邮箱、验证码、身份证、API Key、JWT 和隐藏提示脱敏；
- 普通六位数字硬负例；
- 中文、英文数据密级上下文和角色等级；
- “内部结构”“秘密花园”等普通词义硬负例；
- BGE 正常中文/英文输出误报。

## 语义算法结果

### BGE 风险相似度

使用固定分层抽样：AlignBench 输入 98 条、输出 98 条，SafetyBench 各类别共 140 条。

| 数据 | 修复前误报 | 修复后误报 |
|---|---:|---:|
| AlignBench 输入抽样 | 0/98 | 0/98 |
| AlignBench 输出抽样 | 2/98 | 0/98 |
| SafetyBench 输入分层抽样 | 0/140 | 0/140 |

### v2 微调 Transformer 分类器

模型元数据报告内部测试集：准确率 `0.8033`、宏 F1 `0.8331`。但独立数据按“最高标签非 normal”评测时：

| 数据 | 非 normal 数量 |
|---|---:|
| AlignBench 输入 | 651/683 |
| AlignBench 输出 | 654/683 |
| SafetyBench 中文输入 | 9,839/11,435 |
| Chinese Do-Not-Answer task2-FP | 623/899 |

这表明当前模型把大量一般中文语义映射到七类安全标签，不满足生产启用标准。提高置信阈值到 0.95 虽可降低独立数据误报，但会把模型自有测试集的风险召回率从约 `97.0%` 降到约 `18.9%`，因此没有采用这种安全弱化方案。

## 复现

先从官方仓库按其许可证下载以下文件到同一目录：

- `safetybench_test_zh.json`
- `alignbench.jsonl`

然后运行：

```powershell
python evaluation\scripts\eval_io_guard_academic_zh.py `
  --data-dir <数据目录> `
  --output <结果 JSON 路径>
```

运行仓库最小学术夹具：

```powershell
python -m pytest `
  clawguard\modules\io_guard\original\tests\test_academic_zh_safety.py `
  -q
```

语义模型权重不提交 GitHub。BGE 和 Transformer 专项测试会在对应本地权重存在时运行，否则按仓库约定跳过。

## 上线建议

1. 当前线上继续使用 `semantic_ab_A_rules.json`，避免不合格的 v2 分类器进入请求链路。
2. BGE 策略可以用于受控 A/B 评测，但应继续扩展跨语言正常输出原型。
3. v2 分类器重训时，应加入 AlignBench、SafetyBench 分类题、Chinese Do-Not-Answer task2-FP 和业务正常流量作为 OOD/硬负例；训练后必须分别报告输入和输出的召回率、误报率与置信校准曲线。
4. 将本报告的最小夹具加入 CI；完整学术数据仅在许可证允许的离线评测环境运行。
