# 规则完善方案 — Windows + Linux 跨平台完整规则集

> **问题**：现有 `v3/rules/resources.txt` 只有 Windows 路径且覆盖面窄，无 Linux 规则，权限粒度"不够"。
> **产出**：
> 1. 现状缺口分析
> 2. 排查中发现并修复的 3 个引擎 bug
> 3. 完整跨平台规则集 `v3/rules/resources_win_linux.txt`（已通过全矩阵验证）
> **日期**：2026-07-31

---

## 一、现有规则缺口分析

以 `v3/rules/resources.txt` 为基准：

| 缺口 | 现状 | 影响 |
| --- | --- | --- |
| Linux 路径完全没有 | 只有 `C:\`、`D:\` 风格 | Linux 部署（/etc、/home、/root…）全部零信任拦截，无法用 |
| Windows 系统目录缺失 | 无 `C:\Windows`、Program Files、system32 | 系统目录退化为"未列默认拒绝"，可访问性全靠碰运气 |
| 盘符根兜底缺失 | 只有 `C:\Users` 一条，无 `C:\`、`D:\` 根 | 未列子目录不可达，规则必须穷举到叶子 |
| 用户目录树不完整 | 只有 admin/public/guest 三层 | admin 的 Desktop/Documents/AppData/.ssh/secrets 无分层策略 |
| 工具分类太粗 | 仅 read/write/execute_bash/query_weather | 缺 web_search、delete_file、http_request、code_interpreter 等 |
| 数据库是占位符 | `db:public/internal/...` 抽象命名 | 无法对接真实库名 |
| 文件级规则缺失 | 无"具体文件"示例 | 无法精细到单文件（如 `.ssh/id_rsa`、`/etc/shadow`） |

> 结论：规则"不够"是**设计问题**——没有按树状继承思维组织，导致要么穷举、要么漏配。

## 二、排查中发现并修复的 3 个引擎 bug

为让跨平台规则跑通，深入验证时发现规则引擎本身有 3 个真实缺陷（`v3/auth_gateway.py`）：

### Bug 1：行尾注释破坏第三列继承模式

规则文件第三列后写注释（如 `... | override  # 公开区`），解析器把注释并进 `inherit_mode`，导致 `override` 全部失效、被当成普通规则。

**修复**：`_split_line()` 用 `re.sub(r"\s+#.*$", "", seg)` 剥离每段行内注释（要求 `#` 前有空白，避免误伤含 `#` 的路径）。

### Bug 2：Windows 盘符冒号被误判为工具命名空间（严重）

树状匹配用 `":" in pattern` 判断工具规则，但 `C:\...` 的盘符冒号同样触发 → 所有 Windows 路径深度被算成 `100+1=101`，**Windows 路径的树状层级完全失效**，override/继承形同虚设。

**修复**：新增 `_is_namespace_pattern()`，排除 `盘符:\` 形态（`pattern[1]==':'` 且首字符是字母），Windows 路径按真实层级计深度。

### Bug 3：路径前缀无分隔符边界

非通配路径 `C:\Users` 用子串匹配，会误中 `C:\Users2\...`。

**修复**：`_match_pattern()` 对路径模式改为"精确或分隔符边界前缀"（`startswith(pattern + "\\")`），`C:\Users` 不再误中 `C:\Users2`。

**验证**：测试套件 11 → 13 组全部通过；20 资源 × 4 等级全矩阵与预期一致。

## 三、完整规则集设计

新文件 `v3/rules/resources_win_linux.txt`，设计原则：

1. **根/盘符/主目录默认 internal(inherit)**，敏感子目录用 override 收紧 → 规则从"穷举叶子"压缩到"每层一条"
2. **文件级规则**（`/etc/shadow`、`.ssh\id_rsa`）比目录通配更具体，同深度自动优先
3. **工具分四档**：public 查询 / internal 读 / secret 写 / top_secret 执行
4. **未列出的资源默认 99 级** → 零信任

### Windows 规则骨架

```
C:\                      | internal | inherit    # 盘符根兜底
C:\Windows\*             | top_secret| override
C:\Program Files\*       | secret    | override
C:\Users\*               | internal  | inherit    # 用户树
C:\Users\Public\*        | public    | override
C:\Users\admin\*         | secret    | override
C:\Users\admin\.ssh\*    | top_secret| override
C:\Users\admin\secrets\* | top_secret| override
```

### Linux 规则骨架（FHS 标准）

```
/                        | internal  | inherit
/etc/*                   | secret    | override
/etc/shadow              | top_secret| override   # 单文件级
/usr/*  /bin/*  /boot/*  | secret    | override
/proc/*  /dev/*          | top_secret| override
/var/*                   | internal  | inherit
/var/www/*               | public    | override
/home/*                  | internal  | inherit
/root/*                  | top_secret| override
```

## 四、使用方式

```bash
# 方式一：环境变量切换（不动现有 demo 规则）
set CLAWGUARD_RESOURCES_FILE=E:\tiaozhanbei\MAC\v3\rules\resources_win_linux.txt
py -3 auth_gateway.py check user_01 /etc/shadow '' ''

# 方式二：直接替换现有规则文件
copy resources_win_linux.txt rules\resources.txt
py -3 auth_gateway.py reload
```

注意：本机为 Windows，fnmatch 的 `normcase` 会统一大小写（Linux 部署时如需大小写敏感需在引擎层调整）；`/` 与 `\` 分隔符两种写法均可用，Linux 规则建议统一正斜杠。
