## 二、与经典 MAC 模型的对照

我们的实现横跨了传统信息流安全的三代模型，这在申报时是很好的理论支撑：

| 经典模型 | 核心规则 | 我们 v3 的落点 |
| --- | --- | --- |
| **BLP（Bell-LaPadula, 保密性）** | 下读：`用户密级 ≥ 资源密级` 且类别包含 | `SecurityLabel.dominates()` = BLP 简单安全属性的直接实现 |
| **Biba（完整性）** | 上写：`用户完整性 ≤ 资源完整性` | 未实现，列为下一步（对应写操作的 *-属性规则） |
| **SELinux 类型强制（TE）** | 主体/客体打标签，规则引擎判定域转换 | 我们的规则表 + `check()` 判定流程 |
| **ABAC（属性访问控制）** | 用主体/客体/环境属性做策略判定 | SEAgent 的底座；我们的等级+类别就是结构化属性 |

> 申报价值点：**在单一轻量模块里同时落地 RBAC 与 MAC（BLP 变体），并支持按环境变量一键切换**，这在企业级（政企军工场景）是"可裁剪、可合规"的卖点。

## 三、我们 v3 已实现的创新点（可直接申报）

以下全部为 [v3/auth_gateway.py](../v3/auth_gateway.py) 中已实现、测试通过的代码：

### 创新点 1：三列式跨平台树状继承规则引擎

传统 MAC 规则要么是扁平 ACL，要么需要专业策略引擎（SELinux/OPA）。我们把规则压缩成一行三列文本：

```
路径模式 | 所需等级 | 继承模式(flat/inherit/override)
C:\Users\admin      | secret      | override
C:\Users\admin\temp | internal    | override
```

**优先级判定三要素**（`_resource_required_level_tree`）：
1. 深度优先：路径越深越具体 → 越优先
2. override 压过同深度 inherit/flat
3. 同深度更具体模式优先（通配符更少、字符串更长），与文件顺序无关 ← **本次修复新增**

对应论文 3（AC4A 资源类型树）的轻量工程实现，但进一步引入了传统 MAC 的 override/inherit 语义，规则量级从"每个文件一条"压缩到"每层一条"。

### 创新点 2：RBAC / MAC / Hybrid 三模式一键切换

```bash
ARGUS_MODE=rbac    # 基于角色（默认，兼容 v2）
ARGUS_MODE=mac     # 强制访问控制（BLP 格模型）
ARGUS_MODE=hybrid  # 双重校验，RBAC 与 MAC 都通过才放行
```

对比论文 1（SEAgent 纯 MAC）：我们允许在**同一套规则文件**下切换管控模型，部署方可按合规要求选择"宽松 / 强制 / 双保险"。这在政企场景是差异化卖点。

### 创新点 3：MAC 安全标签的"等级 + 类别"格判定

```python
SecurityLabel(level, categories)   # 等级 1..4 + compartment 类别集合
label.dominates(other)  # level >= other.level 且 categories 包含
```

`categories` 实现 SELinux 式的 compartment 隔离（如 `{"财务","核心"}`），是传统 RBAC 等级模型不具备的维度，对应论文 2 的"数据隔离"属性。

### 创新点 4：规则即配置 —— 文本热更新 + SQLite 双后端

- 规则用纯文本，改完 `reload_rules()` 即生效，无需重启
- 同一套 CRUD 接口自动适配文本文件 / SQLite 两种后端（`_RuleBackend` 抽象）
- 提供完整增删改查：`add/remove/get/list_*_rule`，并已接 CLI（`add-user`/`remove-user`/`add-resource`/`remove-resource`）
- `check_reason()` 返回判定原因，可直接喂审计日志

对应论文 4（AgentSpec 的 DSL）"规则与引擎分离、确定性执行"的理念，但用可读文本而非新 DSL，学习成本更低。

### 创新点 5：特例机制 —— 等级之上的越级放行 / 显式拒绝

```python
adminuser   | top_secret | *                    # 全放行
auditor_01  | internal   | !tool:write_file, tool:read_file  # 禁写 + 只读
```

对应论文 2 的"来源授权"：特例优先级高于等级比对，`!` 前缀显式拒绝 Fail-Safe。是 RBAC 等级批量管理与个别授权解耦的工程化手段。
