## 八、新增：5分钟窗口保留 + 近永久隔离（需管理员解除）

> **设计：** 5分钟滑动窗口（AuditRiskMonitor 300s + DynamicLinePolicy penalty 0-2）原样保留，用于实时防线升级与 human_review 二次审批；在此之上叠加 **近永久标记**，达到阈值即写入 
> untime/quarantine/quarantine.json，永久生效直到管理员 POST /v1/admin/quarantine/clear 解除。

### 触发条件（满足任一即永久）

- **5分钟窗口** lock_count >= 8（CLAWGUARD_QUARANTINE_BLOCK_COUNT，默认8次）
- **高风险+频探** probe_likely && risk_score >= 0.85（CLAWGUARD_QUARANTINE_RISK_THRESHOLD）
- **1小时长窗口** lock >= 15（CLAWGUARD_QUARANTINE_LONG_WINDOW_COUNT，默认15次，历史因素累计）

### 隔离语义

- 已隔离用户：check_v4 原来 llow 的请求 → human_review（必须人工审）；原来 lock 的仍 lock（最高防线）
- 未隔离用户：仍走 5分钟 penalty 升级 → llow / block / human_review；若本次评估达到永久阈值，**本次返回仍按5分钟逻辑**，但已写入隔离，下一次请求起永久生效
- CLAWGUARD_QUARANTINE_ENABLED=0 可一键关闭永久层，不影响5分钟；CLAWGUARD_QUARANTINE_PATH 可指定文件（测试用     mpdir/q.json 隔离）

## 九、RBAC/MAC 融合创新：模糊格支配 + 历史职责分离（HB-SoD）

### 1. 论文内容

**1.1 模糊多级安全 Fuzzy MLS**

- 经典 MAC 硬支配 0/1 无法容忍临界，Fuzzy MLS 将 dominates 改为隶属度 μ(level_diff)*μ(cat_overlap)*μ(1-risk) 的 Mamdani 推理，输出 allow度 0~1 再阈值化。
  **1.2 历史职责分离 HB-SoD**
- RBAC SoD 扩展为历史不能：history:block>3 表示5分钟内被拦截>3次则本会话禁用人该类特权，即使RBAC/MAC放行也转人工。
  
  ### 2. 我们的实现（保留格）
- auth_gateway.py: SecurityLabel 新增 fuzzy_score/dominates_fuzzy，_check_rbac 增加 risk_score 惩罚与 _check_history(history:block>3) 优先检查。
- 与 5min+永久隔离协同：penalty 实时收紧、fuzzy 风险越高越难支配、history 行为污点、quarantine 跨会话永久，四层正交。
- 演示：history:block>3 触发 human_review，fuzzy 让 secret 读 top_secret 在高风险时自动 human_review。
