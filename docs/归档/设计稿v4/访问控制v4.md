## 一、 适配器核心逻辑 (`access_control_adapter.py`)

适配器的核心职责是**数据格式转换与异常隔离**：将网关接收的 `SecurityRequest` 转换为底层引擎入参，再将判定结果封装为统一的 `ModuleResult`。

### 核心代码逻辑

```python
class AccessControlAdapter(BaseAdapter):
    name = "access_control"

    def run_sync(self, request: SecurityRequest | dict) -> ModuleResult | dict:
        try:
            # 1. 提取参数、自动补齐 tool: 前缀 (修复 Bug)、规范化路径
            user_id = str(context.get("user_id", "default_user"))
            tool_name = str(payload.get("tool_name", ""))
            if tool_name and not tool_name.startswith("tool:"):
                tool_name = f"tool:{tool_name}"

            path = os.path.normpath(arguments.get("path", "")) if isinstance(arguments, dict) else ""
            database = str(payload.get("database", ""))

            # 2. 调用底层 RBAC/MAC 核心判定引擎
            result = check_v4(user_id=user_id, path=path, tool=tool_name, database=database)
            allowed = bool(result.get("allowed", False))

            # 3. 封装为统一 ModuleResult (action 仅为 allow 或 block)
            return ModuleResult(
                module=self.name,
                success=True,
                action="allow" if allowed else "block",
                risk_score=0.0 if allowed else 1.0,
                reason=result.get("reason", ""),
                details={"user_id": user_id, "tool": tool_name, "path": path, "database": database},
                latency_ms=round(latency, 3),
            )
        except Exception as exc:
            # 容错隔离：异常时默认安全拦截，防止主网关崩溃
            return ModuleResult(module=self.name, success=False, action="block", error=str(exc))
```

## 二、 调用与接入方法

### 2.1 主网关调用示例

在 FastAPI 安全网关的 **`tool_pre`（工具调用前）** 路由处理中直接调用：

```python
from clawguard.adapters.access_control_adapter import AccessControlAdapter

adapter = AccessControlAdapter()

# 1. 在 /v1/tool/pre_check 接口中发起校验
result = adapter.run_sync(security_request)

# 2. 如果判定为 block，直接终止后续执行并返回原因
if result["action"] == "block":
    return SecurityResponse(action="block", reason=result["reason"])
```

### 2.2 接入数据契约示例

- **请求输入 (`SecurityRequest`)**：
  
  ```json
  {
    "context": { "user_id": "user_01", "stage": "tool_pre", "trace_id": "trace-001" },
    "payload": {
      "tool_name": "read_file",
      "arguments": { "path": "C:\\demo\\test.txt" }
    }
  }
  ```

- **响应输出 (`ModuleResult`)**：
  
  ```json
  {
    "module": "access_control",
    "success": true,
    "action": "allow",
    "risk_score": 0.0,
    "reason": "allow: 用户等级 2 ≥ 资源所需 2",
    "details": {
      "user_id": "user_01",
      "tool": "tool:read_file",
      "path": "C:\\demo\\test.txt"
    },
    "latency_ms": 0.35
  }
  ```

## 三、 已修复 Bug：工具名称格式不一致导致的误拦截 Bug

- **Bug 现象**：
  OpenClaw 传入的 `payload.tool_name` 格式为裸工具名（如 `"read_file"`、`"query_weather"`），而规则库 `resources.txt` 中配置的资源模式均带有 `tool:` 命名空间前缀（如 `tool:read_file`）。

- **导致后果**：
  匹配机制无法直接比对两者，导致未命中任何规则，降级触发零信任默认规则（`DEFAULT_RESOURCE_LEVEL = 99`）。正常用户（如 `user_01` 等级 2）在调用合法工具 `read_file`（等级 2）时，被错误阻断判定为 `block: 用户等级 2 < 资源所需 99`。

- **修复方案**：
  在适配器 `access_control_adapter.py` 参数提取阶段自动补齐 `tool:` 前缀，解决兼容性 Bug：
  
  ```python
  tool_name = str(payload.get("tool_name", ""))
  if tool_name and not tool_name.startswith("tool:"):
      tool_name = f"tool:{tool_name}"
  ```
