# 给测试人员的一页纸（怎么跑、看什么、怎么报）

> 这是一套给 AI 智能体安全防护系统 **Argus** 的测试集，共 **550 条**，每条都自带「标准答案」。
> 你只需要：**喂进去 → 看它给的结果 → 和标准答案比对**，就知道每道安检拦得准不准、有没有误拦。

---

## 二、三条使用路径（按你的角色选）

### 路径 A：只要"看"结果（给评委 / 客户 / 领导）
直接打开这两个文件，不用装任何环境：
- `测试场景手册_通俗版.md` —— 10 道安检是干嘛的、每个功能"你这样做→系统这样反应"。
- `预期输出对照表.csv`（Excel 打开）—— 按"功能/类别/预期输出"筛选，一屏看全 550 条。

### 路径 B：要"跑"自动评测（开发 / 测试工程师）
```bash
# 0. 定位被测代码目录（本测试集随仓库分发时自动探测 <仓库根>/terminal，也可手动指定）
#    export ARGUS_REPO="<仓库根目录>/terminal"

# 1. 单模块评测（最推荐，从简到繁）
python eval_dataset.py --dataset sandbox_harm_detector      # 纯正则，零依赖，最快
python eval_dataset.py --dataset access_control_matrix       # 纯规则（先配 users.txt 等级）
python eval_dataset.py --dataset audit_events.synthetic      # 离线，验证图构建/风险联动
python eval_dataset.py --dataset io_guard_input              # 本地模型头，可离线
python eval_dataset.py --dataset io_guard_output
python eval_dataset.py --dataset io_guard_content
python eval_dataset.py --dataset retrieval_guard             # B层注入需 torch+PIGuard
python eval_dataset.py --dataset tool_guard_intent           # 需配置 TOOL_GUARD_LLM_*
python eval_dataset.py --dataset media_input                 # PDF 需 pymupdf，图片 OCR 需 RapidOCR

# 2. 全部跑一遍（汇总命中率）
python eval_dataset.py --all
```

### 路径 C：只做"行为验证"（多用户登录）
`openguard_auth.jsonl` 是接口行为测试（注册/登录/登出/改角色/禁用账号/配额/SSO），
字段是 `method + endpoint + expected_status`。启动 OpenGuard（8001 端口）后，用 Postman /
脚本逐条发请求，比对返回的 HTTP 状态码。

## 三、看什么（怎么判断"好"）

跑 `eval_dataset.py` 会输出每个模块：
- **命中率** —— 实际结果 == 标准答案 的比例，越高越好。
- **Recall / Precision / FPR** —— 拦截类：Recall 高=漏拦少，Precision 高=误拦少，FPR 低=正常流量没被误伤。
- **混淆矩阵** —— 哪些"该拦截"被放行了（漏报）、哪些"该放行"被拦了（误报）。
- **按 category 命中** —— 哪类攻击拦得好、哪类还有漏。

## 四、测试前必须知道的 3 件事

1. **访问控制要配等级**：`access_control_matrix.jsonl` 跑之前，先在
   `rules/users.txt` 配好 `u_public(L1) / u_internal(L2) / u_secret(L3) / u_admin(L4)`。
   其中 `risk_escalation` 类样本是"审计风险联动二次审批"测试——它会临时写几条拦截事件，
   验证"反复试探→防线升级→转人工审批(human_review)"。

2. **有些模块要模型/LLM**（离线跑不了，详见 `offline_subset.md`）：
   - 检索安全 B 层注入 → torch + PIGuard 模型
   - 工具安全意图裁判 → 配 `TOOL_GUARD_LLM_*`（否则只对"应拦截"样本命中）
   - 附件图片 OCR → RapidOCR

3. **沙箱有 3 条"探测器盲点"样本**（`hd-006 / hd-011 / hd-025`，note 里已标注
   【探测器盲点：应拦截但当前漏检】）。这 3 条是故意留的：标准答案写的是"安全上应该拦"，
   但当前 `harm_detector.py` 的正则覆盖不到（python 元组 IP 反弹 shell / nc -e / base64 -d 解码执行）。
   它们跑出来会"命中失败"，**这是预期结果**，用来暴露探测器的漏检点，方便后续补正则——不是数据写错了。
